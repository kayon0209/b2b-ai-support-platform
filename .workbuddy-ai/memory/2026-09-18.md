## Audit round 5 + repairing a broken working tree

**Another agent worked in this repo between sessions.** `b53282e
feat(knowledge): add PDF/DOCX document parser to the ingestion pipeline` was
committed during a ~9 hour gap, and it also left an **uncommitted, broken**
change in `agent_runtime/qa_path.py`.

### The broken tree (fixed in 5facaf5)

`qa_path.py` had an uncommitted, in-progress attempt at the
`ambiguous-refund-eligibility` gap: a module-level frozenset
`_AMBIGUOUS_IDENTITY_TERMS` built from `_stem`, defined 165 lines *above*
`_stem`. Importing the module raised `NameError: name '_stem' is not defined`,
so **the whole application failed to start and no test could even collect**.

Repaired non-destructively: moved the block below its dependencies
(`_stem`, `_query_terms`). The feature is NOT wired in — left as found.

**Why it must not be wired as-is**: `"are"` is in the identity-term set, so
the general question `"Are monthly plans refundable?"` — an eval case that
must be **answered** with "14 days" — is flagged as identity-dependent.
Verified directly:
`_is_identity_dependent("Are monthly plans refundable?") is True`.
The real fix for the gap is account-identity resolution before retrieval,
not pattern-matching the question. This is the second time an attempt at this
gap has been wrong; the eval case is deliberately marked `must_abstain` so it
stays visible rather than being relaxed to whatever the system does.

### Audit round 5 findings

- **Clean**: the outbox relay (at-least-once, `attempts` bumped on claim,
  `mark_failed` records `last_error` and leaves the row queued so it is
  retried and eventually parked visibly); the metrics wiring
  (`get_metrics()` across the orchestrator, `http_requests_total` in the
  middleware, `render_metrics()` in the observability router,
  `HttpMetricsMiddleware` registered in `main.py`).
- **Fixed (5cf2c22)**: `worker.runner` constructed a `PriorityQueueManager`,
  exposed it via a `queues` property, and the docstring claimed the workers
  "share the admission and priority logic in evaluation.queues". Nothing
  consulted it — `next_job`, `backoff_for`, `QueueFull` have **zero** callers.
  Backpressure here is structural (table + `FOR UPDATE SKIP LOCKED` + separate
  worker processes), and a per-process queue cannot coordinate admission
  across processes. Removed the dead construction/property/config field and
  corrected the docstring; `evaluation/queues.py` keeps its tested model with
  a note that it is deliberately not wired in.

### Pattern across all audit rounds

Six defects, six of the same family — **a value or capability that exists but
is never consumed**:

| # | Defect | Missing piece |
|---|---|---|
| 1 | `AgentRun.started_at` never written | writer |
| 2 | `AgentRun.token_usage` never written | writer |
| 3 | `sweep_expired_data` never called | caller |
| 4 | `credential_ref` never dereferenced | consumer |
| 5 | priority-queue admission never consulted | consumer |
| 6 | `_is_identity_dependent` never called (and unimportable) | caller |

The cheap, high-yield check: for any field/function a reader depends on, grep
for its *writers/callers*. Docs and tests that call a function directly will
not reveal a missing production caller.
