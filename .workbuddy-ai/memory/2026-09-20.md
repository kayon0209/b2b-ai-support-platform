### 根因与修法
`orchestrator._dispatch` 要求同时有 `chatwoot_account_id` 和 `chatwoot_conversation_id`，
缺任一就返回 `OUTBOUND_TARGET_MISSING` → run 标 FAILED → agent turn 不落库（只有 completed 才写）。

所以每一条平台侧答案都被判成"投递失败"而被丢弃。

修法（判据是查出来的，不是猜的）：
- **缺 account_id** = 这个会话根本不是 Chatwoot 的 → 没有可失败的投递 → 返回 ""（成功）。
  实锤：真 Chatwoot 事件的 payload 带 `chatwoot_account_id`（"3"/"7001"），触发接口建的事件没有。

## ⚠️ 事故：本地 .git 的 refs 与 loose objects 被删（已恢复）

现象：`git commit` 报 `invalid object ... customer_router.py` +
`fatal: your current branch 'master' does not have any commits yet`；`git show-ref` 空。

实况：`.git/refs/heads/` 整个目录消失；12:03 UTC 之后创建的 loose objects（我的 4 个提交
及新 blob）全部丢失；只剩那个旧 pack。**另一个会话的 60+ 未提交改动在工作区，一旦
`reset --hard` 就全没了** —— 所以我全程没碰工作区。

恢复（全部只读/只写 .git，不碰工作区）：
```bash
tail .git/logs/refs/heads/master          # 1) 从 reflog 拿到最后的 sha
git fetch origin                          # 2) 远端有全部提交，拉回对象 + refs
git update-ref refs/heads/master origin/master
rm -f .git/index && git reset --mixed HEAD  # 3) 重建索引；--mixed 不动工作区
git fsck --no-progress --no-dangling      # 4) 校验：无输出=干净
```
结果：HEAD 回到 `7304593`，fsck 干净，73 条工作区改动（含对方全部未提交内容）完好。
推测原因：某种清理（沙箱 safe-delete guard / git gc）删了 `.git/refs` 与 loose objects。
**未最终证实。**

教训：**这个仓库的工作区是两个人共用的，任何 `reset --hard` / `checkout --` /
`clean -fd` 都会毁掉对方未提交的工作。** 只做 `update-ref` + `reset --mixed`。

并**逐条否决了"调阈值"**：

| 被否决的做法 | ADR 给的理由 |
|---|---|
| 调低 `min_abstention_correct_rate` | **全局放松**：同时放松敏感请求/越权提问/注入攻击的全部弃答契约，"拿最重要的安全门去换一个语言问题" |
| 加 `KNOWN_GAPS` 白名单 | 豁免口一旦为"已知缺陷"打开就再也关不上 |
| 标成 `must_abstain=True` | 语义撒谎，且让中文检索缺口永远不被测量 |

它的解法是**按原因划适用域**：`cross_lingual=True` + `NO_AUTHORIZED_EVIDENCE` 同时成立才不计入
弃答率分母，且**必须**累加进新指标 `cross_lingual_unreachable` 并断言非零——
"如果一个缺口被排除在分母外，就必须有一个数专门记住它存在"。默认 fail-closed。

**结论：任务 B 按我原来的设想（调检索分数阈值）不该做**，而且会直接和 ADR 0009 的方向打架。

### 定位方法（可复用，PowerShell 在本机被沙箱拦截）
1. `netstat -ano | grep ":5435"` 列出连库的 PID（**别写成 `5435|5432`，会误匹配 54323**）；
   连着库却**不监听端口**的 python = worker 形状。
2. 决定性一步：隔离环境装 `psutil`（**没污染项目 venv**）读完整命令行：
   `"C:/Users/Rose/.workbuddy-ai/binaries/python/envs/default/Scripts/python.exe" -c "import psutil; ..."`
   → 按 `worker.runner` 过滤即可列出所有 worker。
3. `tasklist /V` 给不出命令行（窗口标题是"暂缺"）；CPU 时间（如 5139s）是很强的旁证。

### 教训
- **起 worker 后必须能按进程树停掉**；只停 shell 会留孤儿，而且它们会静默污染所有队列测试。
- `pg_stat_activity` 抓不到它们：那些是池化连接（idle/COMMIT），且 Docker 端口代理会改写
  宿主侧源端口 → `client_port` 与宿主 `netstat` 本地端口对不上，这条映射在本机走不通，别再试。
