## 关键环境事实（重要，避免重复踩坑）

- **Python 必须用绝对路径 PYTHONPATH，且 Windows 上分隔符是 `;` 而非 `:`**
  正确写法（bash 下）：
  ```
  R="D:/360Downloads/360驱动大师目录/b2b-ai-support-plan/b2b-ai-support-plan"
  export PYTHONPATH="$R/apps/api/src;$R/packages/contracts/src;$R/packages/policy/src;$R/packages/observability/src"
  ./.venv/Scripts/python.exe -m pytest -q
  ```
  用相对路径或 `:` 分隔都会得到 "No module named 'platform_core'"，
  会误判为"13 个测试文件全部无法收集"。
- venv 位于 `.venv`（Python 3.12.0，来自系统 Python，非 managed runtime）。
- Docker 端口：ai-postgres `5435`、chatwoot-postgres `5434`、ai-redis `6380`、
  chatwoot-redis `6381`、Chatwoot `3000`、API `8000`、Keycloak `8081`、MinIO `9000/9001`。
- `platform_app` 角色已存在（NOBYPASSRLS），用于 RLS 负向测试。

## 已知未解决的坑（下次优先处理）

1. **目录不是 git 仓库** —— 无版本历史/无回滚能力。建议立即 `git init` 建基线。
2. **mypy strict 形同虚设** —— `packages/*/src/__init__.py` 均为 0 字节，
   导致 "Duplicate module named `__main__`" / "Source file found twice"，
   mypy 报错后即停止检查，实际未检查任何代码。需调整 `mypy_path` /
   `--explicit-package-bases` 或移除多余空 `__init__.py`。
3. **发送前租约重检缺调用点** —— `identity/control_lease.py` 的 CAS 能力已就绪，
   但编排层尚未存在，故无调用方。属安全红线缺口。
4. **`embed_deterministic` 是哈希占位** —— 命名清晰但易被误认为真实 embedding。
