# ADR 0015: 以会话租约作为坐席收件箱的主对象

日期：2026-09-24
状态：已实施第一阶段；生产验收见 [工作台验收清单](../workbench-redesign-acceptance.md)。

## 背景

旧 `/admin/workbench` 从 `GET /v1/cases` 获取工单，再由工单关联查询聊天记录。然而 AI 的人工交接会释放控制租约到队列，不保证创建工单。因此一条正在等待人的客户会话可能完全不出现在旧工作台。这个缺口无法通过扩宽原有对话卡片解决。

## 决策

1. 收件箱以本租户 `ConversationControlLease` 中的 `queue` 和 `human` 记录为准；工单与企业账户通过各模块的应用接口附加，不作为入队前提。
2. 认领、转交、退回队列、结束使用租约行锁和 `expected_version`。actor 从认证上下文取得，不能由客户端指定。
3. 人工回复只允许当前所有者或尚未被领走的会话；同一幂等键的重试不重复写消息或出站事件。
4. 人工回复后会话标为 `HUMAN_WAITING_CUSTOMER`；客户回复使之回到 `HUMAN_ACTIVE`。显式结束标为 `closed/RESOLVED`。这不是 Case 的解决状态，工单生命周期仍由 Case 命令管理。
5. 满意度仅在结束且存在真实人工回复时提出。客户继续咨询时开启新的访客会话，从而使旧评价与新问题分离。
6. 网页客户继续按可见性控制的短间隔读取会话，以看到人工消息；引入推送连接前需先测并发负载，无新基础设施。

## 结果与限制

- 无工单的转人工会话可被接待。
- 客户、坐席、工单三个状态各有明确主对象，避免“工单关闭等于聊天结束”的隐式推断。
- 关联工单的负责人会随接入和转交同步；结束会话不会自动解决工单。
- 当前没有主管强制抢占、客户可见文件发送、模型建议重新生成和渠道送达回执 UI。这些能力需要独立授权、审计与验收契约。
- 历史 ADR 0001/0010/0011 保留作为决策记录；现行渠道架构以 ADR 0012 与本 ADR 为准。
