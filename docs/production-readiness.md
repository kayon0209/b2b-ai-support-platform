# 生产接入条件与已知限制

本文件统一列出企业部署要求与实现边界，不作为开发任务清单。范围核对日期：2026-10-12；来源为当前代码、2026-10-08 实现记录及较早的环境验证报告。本轮文档修订没有执行生产测试。

## 企业部署输入

| 领域 | 部署要求 | 可核验结果 |
|---|---|---|
| 身份 | 企业 OIDC/SSO、用户/租户/角色映射、允许的回调与注销地址 | 浏览器登录/注销、API audience/JWKS、成员撤权及令牌/会话策略符合企业要求 |
| 企业数据 | 授权 ERP/CRM 等 sandbox、字段契约、凭据引用、记录归属和时效规则 | 查到的是当前客户的记录；写入有确认、幂等、读回与 UNKNOWN 对账；依赖条件写的操作有原子版本控制 |
| 客户渠道 | 选择网页、邮件或微信等目标入口；配置所用渠道的签名/传输 | 网页双端消息可见；外部渠道按 provider 能力检查真实收发、线程关联、失败和不确定结果 |
| 知识与模型 | 获批企业语料、独立审阅的评测集、允许的数据目的地、模型端点与预算 | 按固定集记录质量、拒答、引用、安全、延迟和成本，而不是只报告测试 pass rate |
| 数据与存储 | 非 owner/非 BYPASSRLS 应用角色、独立迁移凭据、私有存储、保留策略、扫描服务 | 租户负例、受控访问、删除/保留、真实备份恢复及文件安全检查 |
| 基础设施 | 镜像与前端构建配置、TLS、安全头、Ingress、连接池、可信代理、监控与 OTLP | 页面/深链/API 可用；预算按副本数核算；告警实际到达接收方；恢复路径可执行 |

## 已知实现限制

| 项目 | 当前边界 | 部署/产品处理方式 |
|---|---|---|
| 队列公平性 | 有租户 API 桶、月度配额和全局队列背压；没有通用租户公平调度或独立队列准入配额 | 容量计划纳入 noisy-neighbor 场景；共享规模需要适用策略 |
| 外部写与撤销 | UNKNOWN 人工对账；唯一已定义的安全补偿为未改动内部 Case 的关闭 | 外部系统走各自业务对账/补偿；不能宣称通用撤销 |
| 文件安全 | 已有类型检查/扫描状态；内置扫描器主要检查文件格式，检索扫描门禁默认关闭 | 部署真正恶意软件扫描器、回填存量状态并显式启用门禁 |
| 合规导出与擦除 | audit/cases 导出、平台联系记忆擦除，不覆盖全部对象字节或外部原文 | 根据法律、数据最小化和交付方式定义范围；不承诺完整数据主体导出/擦除 |
| 工件血缘 | run 有模型/Prompt/检索等版本，部分工件有来源关联 | 没有覆盖所有业务派生物的统一 parent-artifact graph |
| 外部评测来源 | 知识发布有签名评测路径；Prompt summary 外部 CI 签名/provenance 尚未接入 | 两条发布链路分开说明，不能互相替代 |
| 前端生产打包与代理 | API 镜像含 SPA，但默认 Dockerfile 执行普通 `npm run build`；客户前端固定 `/api`，现有 Ingress 不剥离此前缀 | OIDC/API 的 Vite 变量必须进入构建；运行时 ConfigMap 不会重写已编译 JS；完整产品部署需同源 `/api` 重写，见部署指南 |
| 公共入口限制 | API metrics 与业务同端口；示例 Ingress 转发 `/`，没有按 URL 屏蔽 metrics/文档 | 网关显式阻断公网 `/metrics`、`/docs`、`/redoc`、`/openapi.json`，保留内部采集并做外网探针验证 |
| 监控与容量 | Operator CRD、OTLP receiver、proxy CIDR 和 DB headroom 是部署配置 | 实际安装与核验；清单渲染/本地探针不能替代集群结果 |

## 发布范围管理

选定业务范围后，记录版本/commit、环境、企业接入、样本与指标、验证结果、责任人及证据位置。只启用已获准场景和租户；范围外能力写为“不支持”或“需要独立接入”。验证证据充分后更新本文件对应边界，不重复保留失效的开发状态。

质量阈值与故障处置见 [发布检查与 Runbook](launch-checklist-and-runbook.md)，操作步骤见 [部署与运维](deployment-and-operations.md)。
