# 部署分析 — 华秋智联（huaqiu.com）的 AI 客服上线方案

日期：2026-09-19
调研来源：华秋官网、华秋 PCB 帮助中心（hqpcb.com）、华秋商城（hqchip.com）、深圳市发改委报道（文末来源）。
性质：业务调研 + 与本平台的逐项映射 + 上线路线。**每个映射都指向本仓库已实现的具体机制**，缺口如实标注，不做无法兑现的承诺。

## 1. 公司画像

深圳华秋智联股份有限公司（原华秋电子，2011 年成立，2024 年 10 月完成 3.1 亿元融资）
是**电子产业一站式智能基础设施平台**，业务闭环围绕电子工程师：

| 业务线 | 内容 | 客服关联度 |
|---|---|---|
| 电子发烧友网 | 百万工程师社区，流量入口 | 高（咨询入口之一） |
| 华秋 PCB | 1–32 层、HDI、类载板；打样/小批量/大货；自建工厂 + 自研 MES | **最高**（订单/EQ/交期/质量） |
| 华秋 PCBA | 钢网、SMT 贴片、DIP、组装；MES 透明交期 | 高（订单/物料/进度） |
| 华秋商城 | 元器件自营 30 万+ SKU、BOM 配单、海外代购；东莞仓储当日发 | **最高**（货期/发票/退换） |
| 华秋 DFM / AI EDA | 可制造性分析软件、KiCad 发行版 | 中（工具使用问题） |
| 华秋方案 / Layout | 设计服务 | 中（项目制沟通） |
| NextPCB | 英文站（海外） | 中（多语言） |

客服工作时间：**周一至周六 9:00–18:30**。这意味着夜间与周日的咨询（工程师加班调板是常态）
完全落在人工盲区——这是 AI 客服最直接的价值主张。

## 2. 客服的真实日常（已验证的高频场景）

1. **EQ 工程确认**：PCB 订单资料有疑问（阻抗要求、孔径、叠层）时工厂发 EQ，客户
   不确认就不投产。现有渠道是销售来电（容易漏接）、邮件（不常看）、用户中心线上确认。
   **交期从 EQ 确认后起算**——EQ 卡住 = 交期顺延 = 投诉。
2. **交期查询与逾期赔付**：订单投产后系统显示交期；超期未发货触发自动退款承诺。
   "现在到哪一步了 / 什么时候发货"必然是问量第一的问题。
3. **质量投诉与赔付**：全测板承诺开短路直通率 100%，"坏一片赔十片"（有赔偿上限）；
   除板费外不承担其他经济损失（如 PCBA 停工）——赔付边界是高频争议点。
4. **发票**：元器件**普票出库自动开具**；PCB/PCBA 及**专票需发货后手动申请**
   （用户中心 → 发票管理 → 我要开票）；发票信息新增/修改。
5. **货期与库存**：现货当日发，代购/期货以商品页为准——库存和到货时间是**实时数据**。
6. **退换货**：按归责处理（华秋责任 vs 客户责任），涉及充值返现/现金券抵扣的退还规则
   ——条件变体类政策。
7. **BOM 配单**：配单进度、缺料替代建议。

## 3. 场景 → 平台能力映射（逐条对应到已实现机制）

| 华秋场景 | 平台机制 | 状态 |
|---|---|---|
| "我的订单到哪一步了 / 什么时候发货" | 路由 `BUSINESS_READ` → 读工具 `order.get_status`（接华秋 ERP/MES） | ✅ 机制就绪，需写 ERP 适配器 |
| "板子发什么快递 / 单号多少" | `shipment.track`（顺丰/德邦适配器） | ✅ 机制就绪 |
| "专票开了吗 / 怎么申请开票" | 流程答案走 RAG；"帮我申请" → `billing.get_invoice` + 写工具（发货后才可申请=后置校验） | ✅ 机制就绪 |
| "这批库存有货吗 / 货期几天" | 实时数据**必须走工具**（ADR 0006 禁止入 RAG）→ 需新增 `inventory.check_stock` 读工具 | ⚠️ 需新增适配器 |
| "4 层板 1.6mm 绿油 最快几天" | RAG：工艺能力文档 + **变体条件弃答机制**（打样/批量、加急/常规答案不同） | ✅ 机制就绪 |
| "半孔怎么做 / 阻抗公差多少" | RAG + **别名表**（"绿油"→"阻焊"、"半孔"→"半孔径"） | ✅ 机制就绪，需录术语 |
| **EQ 确认** | **`CaseStatus.WAITING_CUSTOMER` 原生对应**：EQ 等待 = 等待客户，SLA 时钟暂停；客户在对话中说"确认，按建议生产" → 工具网关 `human_approval` 类写操作 + 控制租约防人机竞态 | ✅ 机制就绪，需 EQ 适配器 |
| "板子短路了，我要索赔" | 意图 `COMPLAINT` → 弃答转人工，**携带证据与原因码**的私有便签给质检坐席；赔付政策属"高权威文档"，冲突时裁定工作流 | ✅ 机制就绪 |
| "发票抬头错了改一下" | 写工具（低风险，确认绑定 action_hash）→ 或转人工 | ✅ 机制就绪 |
| "退货运费谁出"（现金券订单） | RAG 变体政策（归责 × 是否用券）；识别不准时**宁可澄清** | ✅ 机制就绪 |
| 工程师半夜 2 点问工艺 | AI 7×24 + 弃答生成缺口 → 缺口队列次日人工补答 → **答案沉淀为新文档发布**（数据飞轮） | ✅ 全链路就绪 |

**多语言**：中文检索已内置 CJK 二元切分 + trigram 容错；嵌入模型配置即 Qwen3 系
（`config.py llm_embedding_model`）。NextPCB 英文语料可同平台按空间隔离存放。

## 4. 部署形态：两个选项

**A. 华秋自用（单租户）**：华秋 = 平台一个租户，内部按业务线（PCB/PCBA/商城）
分 **Department**（ABAC 部门隔离已实现）与 **KnowledgeSpace**（工艺能力 / 交易政策 /
元器件 / DFM）。上手最快，数据边界=公司内部门禁。

**B. SaaS 卖给同行（多租户）**：本项目本就是多租户架构——华秋是第一个租户，
后续 PCB/PCBA 同行各自成为租户（RLS FORCE + `platform_app` NOBYPASSRLS +
跨租户负向测试已把隔离做到 L4）。每租户独立的连接器、知识库、配额与计费账本
（billing ledger 已就绪）。**推荐按 B 的架构、A 的节奏上线**：代码不动，
先以单租户运行，商业化的隔离与计费能力天然在位。

## 5. 上线路线图

**Pilot（4–6 周）——官网 + 用户中心，只做"问得到就答、查得到就查"**
1. 种子：`scripts/seed_admin_demo.py` 扩展——租户 `huaqiu`（`data_region=cn-north-1`，
   数据不出境）、客服/技术部门、大客户 `EnterpriseAccount` 分层（战略客户 SLA 档位）。
2. 语料：工艺能力表（**DOCX 表格→原子 chunk 已支持**——工艺参数就是表格）、
   发票/赔付/退换政策（front-matter 标 `doc_type`/`model`）。
3. 别名：`POST /v1/knowledge/aliases` 录入 PCB 术语（绿油/阻焊、半孔/半孔径、
   沉金/化金……）。
4. 工具：`business_api` 连接器指向华秋 ERP 查询网关（`order.get_status` +
   `shipment.track` 先行，`billing.get_invoice` 次之），`credential_ref` 走密管。
5. 渠道：Chatwoot 网站构件挂官网帮助中心与用户中心；webhook HMAC 配置。
6. flag：`agent.business_read_enabled` 对该租户开启；`agent.rerank_enabled` 小比例放量。
7. 验收：跑 eval 语料（新增 EQ/发票/赔付变体用例）+ recall@k 门禁 + 坏一赔十类
   政策题 100% 变体正确率（答错变体比答不出更贵）。

**第二阶段（+4 周）——写操作与 EQ 流转**
- `address.update`（low_write）、`invoice.apply`（confirmed_write，发货后校验）；
- EQ 确认流转：AI 只做"转述 EQ 内容 + 收集确认"，**确认动作本身走 human_approval**
  ——客户在对话里的确认不能直接等于工厂放行，必须有坐席或规则复核；
- 微信公众号/小程序渠道适配器（走 `integrations/sdk.py` 框架，见缺口 1）。

**第三阶段——深化**
- `inventory.check_stock` 实时库存工具（商城侧）；
- BOM 配单进度查询；
- 赔付工单半自动化：质量投诉 → `case.create` + 证据附件（MinIO 预签名 URL）→
  人工裁定；
- 质量看板运营：containment、弃答率、转人工率的周度基线对比（RAGAS 式相对回归）。

## 6. 缺口清单（本项目尚未覆盖、需要开发的）

| # | 缺口 | 影响 | 工作量估计 |
|---|---|---|---|
| 1 | **微信生态渠道**（公众号/小程序/企业微信） | 华秋客户主渠道之一；Chatwoot 需适配器或第三方网关 | 中（走 integrations 框架） |
| 2 | **华秋 ERP/MES 读适配器** | 订单/交期/发票查询的数据源 | 中（`business_api` 契约已定义，对接其接口字段） |
| 3 | **EQ 业务模型** | EQ 是华秋特有流程，需在 Case 上建 EQ 关联或用工具承载 | 中 |
| 4 | **PDF 表格抽取** | 工艺能力表常以 PDF 发布（pypdf 拉平表格） | 已记录约束：需 pdfplumber，违反"不引新依赖"须 ADR |
| 5 | **客服坐席工作台** | Chatwoot 自带，但需培训与话术模板 | 运营工作 |
| 6 | **数据合规审查** | 个保法、Gerber 属客户 IP——平台已"不落原文"（webhook 最小化+哈希），需法务确认 | 流程性 |
