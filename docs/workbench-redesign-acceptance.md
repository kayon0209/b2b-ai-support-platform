## D. 本次检查、环境与边界

- Docker 本地运行 PostgreSQL、Redis、API、交互 worker、outbox worker 和 SLA worker。迁移 0001–0054 成功；API `/healthz` 与认证后的租户 API 返回成功。
- 完整人工旅程使用真实本地 API 与 PostgreSQL：客户转人工 → 无工单会话进队 → 坐席认领 → 人工回复 → 客户端自动看到回复 → 结束 → 客户评分 → 质量接口读取评分。没有配置外部模型密钥或出站渠道，故模型生成、邮箱/微信真实送达不在本次通过范围。
- 集成结果：RLS 跨租户、应用层跨租户、schema 权限、人工接管租约、回复、CSAT、附件授权、case 工作台、客户往返旅程和双坐席并发认领 API 场景通过；完整 `apps/api/tests/unit` 单测集通过。
- 运行状态：Docker PostgreSQL、Redis、API、交互 worker、outbox worker 和 SLA worker 已重建并保持运行；API `/healthz`、前端入口均返回 HTTP 200。交互 worker 使用本地占位模型配置指向 `127.0.0.1:9`，未配置外部模型或出站渠道；日志明确标记 `NO_OUTBOUND_TRANSPORT`，渠道投递不计通过。
- OIDC 结果：隔离的 Keycloak 26.0.8 临时实例签发 RS256 access token；本地 API 实际从 JWKS 拉取公钥、校验 issuer/audience，再通过 `external_identities` 与 membership 解析租户。测试身份映射已清理，临时 IdP 已停止。Auth Code + PKCE 的完整浏览器回跳未完成；该临时 HTTP IdP 的 Secure Cookie 无法由当前自动化 HTTP 客户端在 HTTP 下发送，本次没有绕过这一属性。
- 性能结果：工作台队列计数现拆成队列、当前坐席、等待客户三个精确计数子查询，并新增三个 PostgreSQL 部分索引；迁移使用 `CREATE INDEX CONCURRENTLY`。在 1 万条本地合成队列租约、单个 Docker API、100 并发、队列与详情端点各 1000 次的复测中，队列 p95 为 753ms、详情 p95 为 428ms，2000 次请求全部 HTTP 200。队列页查询使用 `ix_workbench_queue_order`，50 条页扫描约 0.023ms；队列精确计数因样本中的 1 万条均处于 queue 状态，PostgreSQL 仍选择约 1.2ms 的顺序扫描。优化降低了队列延迟，但仍未达到 500ms 发布目标；请求池等待、认证成员解析及生产近似拓扑需继续 profiling。此前 50/100 并发记录来自索引与计数改动前，不应用作本次优化后的结果。
- 构建结果：`npm run build` 通过；缺少 issuer 时 `npm run build:release` 按设计被门禁拒绝，使用 `https://idp.example.test/realms/platform` 与 `admin-web` 作为**仅构建用占位值**后通过。Ruff、11 个变更相关后端源码 Mypy、`git diff --check` 通过。占位 IdP 不代表真实登录验收。
- 维护提示：当前安装的 Starlette `TestClient` 在测试结束时提示未来应迁移至 `httpx2`；这轮用例均通过，该提示不影响运行时 API，但应在测试依赖升级时处理。
- MinIO 没有启动：`minio/minio:latest` 镜像拉取被拒；可拉取的 AIStor 镜像需要许可证。故上传验收不可宣称通过。
- 当前测试数据仅为本地演示租户，不代表多租户 RLS、安全渗透、生产容量或外部渠道验收。
