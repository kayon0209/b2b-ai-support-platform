## 每个任务必须处理的关键点

### T00–T03：理解能力与评估

- 核对 ChatProvider.complete 是否支持所选模型的结构化参数；现有协议是文本生成接口，不能只在 Prompt 中写“输出 JSON”就宣称原生严格结构化输出。
- 优先在协议外做严格 Pydantic 校验；如扩展 provider，保持原生成客户端兼容。
- 请求模型前检查预算、隐私与功能开关；模型失败或非法输出按规则降级，产生 reason_code。
- 现有规则结果与语义结果并存；confidence_band 不进入权限决策。
- 输出样本来源、去重规则、划分清单与错误切片，不提交原始客户历史。
- 真实模型无凭据/无预算时：继续完成 fake provider 下的代码和故障测试；真实质量与耗时标阻塞，不能启用 semantic_read。

### T04–T05：任务与工具

- 锁定 source_turn、task_local_key、action_revision 的定义，建立数据库唯一约束；测试两个 Worker 和进程重启后的同任务重试。
- 任务输出与执行回执分别存储；不能由“LLM 认为完成”直接生成 succeeded。
- 多意图中 A 已完成、B 待补参、C 待人工时，只推进合法任务，不重复 A，不跳过 B 的依赖，不错误结束整场会话。
- 补充字段须注明来源和确认状态；若当前轮与历史字段矛盾，询问用户，不自动采用模型偏好。
- 工具候选名即使存在于平台总目录，当前租户未配置或 actor 无权限仍须拒绝；兼顾读取类工具的记录归属校验。
- 确认绑定当前参数版本，提交后再次鉴权；租约变更、权限撤销、过期确认均不能发起新外部动作。
- 候选参数中的 URL、tenant_id、actor、工具风险等级不接受模型指令覆盖。

### T06–T07：真实产品入口

- 工作台从“刷新已有建议”升级到明确的生成入口；当前用户无 owner 权限时展示原因。
- 原草稿有编辑时，生成结果不能覆盖；插入前提供追加/替换选择，取消不丢稿。
- 引用可点击并校验访问权限；不能把未验证工具结果标为已核验。
- 刷新/切换会话后，服务端恢复任务状态；旧会话返回的异步结果不得进入新会话。
- 工具写入的“待确认”和聊天“发送”按钮必须在文案与布局上区分。

### T08–T09：交付

- 在独立测试租户/数据库执行写入与迁移测试，清理自己生成的数据，保留用户样例。
- 不依赖本地 .env、已热迁移数据库或共享全局状态才能通过；CI 必须从清洁检出初始化。
- 在交付 manifest 中锁定 commit、模型/Prompt/Schema 版本、开关与环境；更换任一条件后必须标记受影响证据过期。
- 最终交付 PR 保持可审阅；本任务没有新增自动合并或生产发布授权。用户将开发交回后由 Codex 出验收结论。
