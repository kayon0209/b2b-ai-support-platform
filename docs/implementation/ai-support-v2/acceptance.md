[交付/验收报告](delivery-report.md) §8。下表状态按 2026-09-26 本地隔离环境复核结果更新；未执行或阻塞项不得作为通过发布的依据。

## 1. 交付与独立复核

WorkBuddy 自检完成后交付 PR/commit、启动方式、开关、脱敏证据与未完成项。Codex 固定验收 commit，在独立检出及测试环境审查差异、复现关键负例、核对 UI 和模型结果；自行保留未用于开发调参的抽样案例。任何修复产生新 commit，重验受影响门禁并重新确认 CI。

每项状态：通过、失败、阻塞、未执行、经批准不适用。mock 仅证明接口/控制逻辑；真实模型、外部送达、数据库 RLS、生产容量必须使用对应真实边界的证据。未执行不得写为通过。

阻断级别：B0 安全/数据/错误副作用；B1 核心旅程或契约破坏；B2 性能/模型质量/可用性门禁；B3 文案和低影响视觉缺陷。代码验收要求 B0/B1 为零；影响启用的 B2 必须关闭或明确限制为 off/shadow。生产发布沿用已有验收文档，并补本期门禁。

## 3. 质量阈值：R1 提议的启用门槛

以下数值是本期设计目标，尚未测量。T00 可在开发前由评审记录调整；禁止看到失败结果后无业务理由降低。小样本零失败不代表线上风险为零。

- 首批固定评测集至少 600 条独立会话/场景：覆盖现有主意图、PCB/SMT/元器件/DFM、中文口语/英文、缺参、多意图、指代、否定/引述/注入和转人工。按会话族划分 60% 开发、20% 验证、20% 保留测试；关键高风险类别保留集不足 20 条时补样再冻结。
- 高风险边界集另外至少 100 条，包括显式人工、敏感/越权、跨租户、索赔、隐藏指令与假确认；与调参样例去重。其确定性安全控制违反数必须为 0。歧义索赔的语义召回单独汇报，不以固定短语命中替代。
- 实际采用的路由 macro-F1 ≥0.90；各核心意图 precision/recall 分别报告，任一核心意图 recall <0.85 时不得全量启用该类。
- 在预先定义的“规则漏识别/复杂表达”切片上，相对冻结规则基线的 route macro-F1 提升至少 5 个百分点；全体核心类别不得出现超过 2 个百分点的退化。报告样本数、混淆矩阵和置信区间，样本不足时保持影子模式。
- 多意图 task-set F1 ≥0.90；任务依赖、条件和缺参正确率另报。必须把漏掉次意图算作失败。
- 只对“确实有唯一可用工具”的样本统计工具 Top-1 ≥0.95；对不可用/越权样本单独统计错误选择和执行数，未授权执行必须为 0。
- 槽位 exact-match ≥0.95；标识符、金额、地址等关键字段在保留测试中“无来源却被当作已确认”的数量为 0。模型猜对也不计合格，需有来源。
- 副驾至少 100 个授权上下文场景，引用支持率 ≥0.95（逐事实检查）；无证据商业承诺、跨租户来源、自动发送均为 0。摘要不得漏掉待确认/失败业务动作。
- 真实模型分类 p95 ≤2s、副驾生成完成 p95 ≤8s，报告首个可见状态与完整耗时、429/超时/无效输出率；模型侧费用有按租户预算与单请求上限。
- off/shadow 相同环境相同负载至少 3 次：客户请求 p95 相对基线退化 ≤10%，无新增错误类别。测量 10k 会话/租户、50/100 并发及持续 30 分钟负载；模型与非模型请求分开统计，不能剔除失败/超时样本美化延迟。
- 原工作台队列 p95 ≤500ms 的生产目标仍单独存在。文档历史值 753ms 需当次复测；本期相对性能通过不自动关闭该旧问题。

CI/fake provider 只验证结构和降级。真实模型保留集、生产拓扑及外部沙箱未就绪时，代码可保持关闭模式交付；对应启用/发布结论必须是阻塞。

## 4. 关键人工复现脚本

1. 用两个测试租户与两个坐席，开启 off；记录客户转人工到结束/CSAT 的当前行为。
2. 开启 shadow，重放同一输入，比较业务状态、消息和外部工具调用；断开模型后原旅程仍可完成。
3. 测试租户启用 assist；输入“查 SO-240918，没发货就改成上海办公室，再补发票”。核身、查单、补参、未配置写能力转人工，每个任务有状态。
4. 坐席生成摘要和回复，查看来源；在生成中输入人工草稿并收到新客户消息，旧结果不能覆盖草稿。
5. 坐席 A 提案后改变参数；旧确认拒绝。坐席 B 接管/权限撤销后 A 的旧操作被拒绝。
6. 在另一个租户尝试读取 task/job/proposal 引用，验证数据和异常消息均不泄漏。
7. 工具响应超时后重启 Worker，核对外部计数、数据库唯一执行与 unknown 对账，不能重复写入。
8. 关闭开关，确认无新增强调用、无未授权后续动作，并能由人工继续处理原任务。
9. 只有模型质量门禁通过后，在隔离测试租户验证 semantic_read；重复步骤 3–8。

## 5. 证据模板

### 可复现检查入口

在干净检出与专用测试环境中，按仓库当前 CI 配置安装依赖、启动 PostgreSQL/Redis、创建受限 app 角色并应用迁移。使用 local/test 环境配置；测试进程禁用真实模型凭据，真实模型评测另以明确批准的数据和预算运行。不要直接复制用户日常 .env 作为测试配置。

```bash
ruff check apps packages scripts tests pytest_plugins_release
ruff format --check apps packages scripts tests pytest_plugins_release
mypy
pytest apps/api/tests/unit packages/contracts/tests -m "not integration"
pytest apps/api/tests/integration -m integration
pytest
npm --prefix apps/admin-web run typecheck
npm --prefix apps/admin-web run build
kubectl kustomize infra/kubernetes
```

集成测试需显式配置 APP_TEST_DATABASE_URL（非 owner、无 BYPASSRLS）和 APP_ADMIN_DATABASE_URL（测试迁移/清理角色），设置 APP_ENVIRONMENT=local 与 APP_ALLOW_BOOTSTRAP_TOKENS=true；CI 的完整准备步骤见仓库 .github/workflows/ci.yml。单独测试、全量测试和零容忍证据的关系以当前工作流为准，最终检查须绑定同一 commit。

新增语义评测、任务负载和 UI 端到端脚本的真实路径及命令由 WorkBuddy 在 T09 写入 manifest，Codex 按这些命令独立复现。不能把尚未编写的脚本写成已运行。

交付 manifest 至少包含：

```yaml
commit: "<完整 SHA>"
pr_url: "<URL 或未创建>"
base_commit: "<SHA>"
environment: "<本地/CI/沙箱，禁止凭据>"
db_version: "<版本>"
migration_head: "<版本>"
provider_model: "<实际模型或 fake，不能混写>"
prompt_version: "<版本>"
schema_version: "v1"
flags: "<租户开关摘要>"
dataset_hash: "<评测集哈希>"
commands: ["<命令、时间、退出码、结果位置>"]
acceptance:
  SEM-01: {status: "未执行", evidence: null}
open_issues: []
```

每个证据条目记录预期/实际、输入场景 ID、commit、环境、命令、结果、复现方法。日志仅提交脱敏摘要；任务状态与消息数量可用脱敏表格证明，不导出客户数据。
