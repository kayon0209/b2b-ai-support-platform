# 坐席工作台改版：需求与实施规格

日期：2026-09-24
参考蓝图：[workbench-concept.png](blueprints/workbench-concept.png)
架构基线：平台自有客户渠道，见 [ADR 0012](adr/0012-remove-chatwoot.md)；会话收件箱决策见 [ADR 0015](adr/0015-conversation-first-workbench.md)。

## 1. 目标与边界

坐席在一个页面完成“发现待接会话 → 接入 → 读取历史与业务回执 → 编辑建议 → 回复 → 转交或结束”。会话是队列主对象；工单是可关联的业务处理对象。转人工不一定创建工单，因此任何等待人工的会话都必须在收件箱出现。

概念图是视觉与信息架构基线，不是业务数据承诺。姓名、公司、订单、SLA、引用、建议和附件只从授权的真实接口显示；字段缺失时明确写“未记录”，不得用示例值填充。`/chat` 内部旧窗口退休，客户入口为 `/support`，坐席入口为 `/admin/workbench`。

### 角色

| 角色 | 核心任务 | 服务端权限 |
|---|---|---|
| 访客/客户 | 咨询、核身、查看回复与业务卡片、服务结束后评价 | 仅本人访客令牌绑定的会话 |
| 坐席 | 看队列、认领、回复、转交、结束 | `CASE_READ` / `CASE_UPDATE`，操作还检查会话所有权 |
| 主管/管理员 | 查看工单、客户、质量与配置 | 既有 RBAC；转交仍需要当前所有者操作，主管代管需后续单独审批设计 |

## 2. 信息架构与版式

桌面 ≥1321px：导航轨 76px；会话队列 318px；对话区占剩余宽度；AI 副驾 350px。页面高度按可视区域计算。队列、对话、副驾分别滚动；对话输入框固定在对话区底部。右栏为“话术／知识／工具”标签。

761–1320px：队列与对话双栏；副驾以可关闭抽屉出现。≤760px：顶部紧凑导航，队列与对话二选一；对话内返回按钮；副驾抽屉覆盖当前页，可关闭。任何宽度均不得水平溢出。

视觉使用深海军蓝导航、白色会话面、低饱和蓝绿主色、琥珀 SLA 提醒和受限的红色风险提示。风险和状态同时使用文字，不依赖颜色。图标使用同一线性图标体系。客户侧保持轻量页面，但订单回执复用同一 `ToolCard` 数据契约。

## 3. 完整用户旅程与功能要求

| ID | 阶段 | 需求 | 失败/空态 |
|---|---|---|---|
| W-01 | 客户入口 | 带租户标识的链接打开 `/support`；开发环境可用本地 demo 租户 | 生产缺少租户标识时提示使用企业链接，不自动进入其他租户 |
| W-02 | AI 接待 | 客户问答、核身、业务回执、引用与转人工状态可见 | 容量/网络/身份错误给出可操作提示，不能显示假“在线” |
| W-03 | 收件箱 | 待认领、我的会话、等待客户三个标签显示真实会话租约，含数量、最近摘要、渠道、关联工单与 SLA | 没有工单的转人工会话同样出现；列表分页、搜索和空态准确 |
| W-04 | 接入 | 当前坐席用一次操作认领；服务端由认证身份确定执行人并检查租约版本 | 双人并发只允许一个成功；冲突提示刷新，不悄悄覆盖 |
| W-05 | 上下文 | 中栏显示最近会话、AI/人工/客户来源、系统通知及业务卡片；历史可向前翻页 | 业务卡片无结构时不显示原始 JSON；长会话先显示最新消息 |
| W-06 | 回复 | 固定输入框支持编辑 AI 建议、常用话术、表情；Enter 发送、Shift+Enter 换行 | 仅当前所有者可发送；失败保留草稿与幂等键；重复提交只产生一条客户回复 |
| W-07 | 附件 | 已关联工单时可上传证据并在“工具”栏查看 | 工单证据不冒充发送给客户的消息；无工单时显示原因 |
| W-08 | 转交 | 当前所有者可转给本租户的活跃坐席，或退回待认领队列 | 目标不存在、租约变更、无权限时无状态变更 |
| W-09 | 结束 | 当前所有者结束会话；关联工单状态单独维护 | 结束后禁止继续回复旧会话；客户可启动新的会话 |
| W-10 | 满意度 | 结束且确实有人工回复后展示评价，服务端也验证资格 | 转人工当下不弹评价；应答率分母为具备评价资格的会话 |
| W-11 | 客户资料 | 右栏只显示最小必要的账户字段、已绑定联系人与资料来源 | 未绑定账户时明确写未绑定，不从会话猜公司或个人身份 |
| W-12 | 运营回路 | 副驾可查看引用、相似工单、证据和审批入口 | 无模型建议时可人工回复；“刷新建议”只刷新现有建议，不称作重新生成 |

## 4. 当前实施接口

- `GET /v1/workbench/conversations?tab=queue|mine|waiting&q=&limit=&offset=`：租户内真实租约队列及三个标签的总数。搜索范围为已脱敏会话文本、工单标题／ID、精确会话 ID。
- `GET /v1/workbench/conversations/{ref}`：租约、最新 80 条会话、翻页游标、关联工单、账户资料、渠道及最后一条 AI 建议。
- `GET /v1/workbench/conversations/{ref}/timeline?before={turn_id}`：向前翻页。
- `POST /v1/workbench/conversations/{ref}/actions`：`claim|release|transfer|close`，须带 `Idempotency-Key`、`expected_version`。服务端推导 actor；转交目标必须在本租户活跃坐席目录。
- `POST /v1/conversations/{ref}/replies`：客户可见回复，须带 `Idempotency-Key`；重复键返回已接收，不再次投递。
- 复用 `/v1/agents`、`/v1/canned-replies`、`/v1/cases/{id}/attachments`、`/v1/cases/{id}/workbench`、`/v1/identity/accounts`。
- 队列和当前会话的 `GET /v1/workbench/*` 使用单独、按租户隔离的高容量限流桶；工作台写操作继续使用通用交互 API 限流，避免 1000 个活动窗口因队列轮询耗尽写操作预算。

所有读写经认证成员、策略检查和租户 RLS。访客令牌仅可读写自身会话。操作只记录业务状态、长度与标识，不能把原文、令牌或附件内容放进审计日志。

## 5. 需求补全与实现条件

1. **真实身份。** 生产后台使用 OIDC 授权码与 PKCE；本地开发才保留人工令牌入口。生产静态站点仍需配置 HTTPS、安全响应头及 IdP 回调地址，并完成真实 IdP 验收。
2. **真实业务源。** 生产启动拒绝 demo ERP 与公开参考价目表；订单、物流与报价能力必须接入本租户已授权数据源。无接入时显示“未配置／不可用”，不展示虚构订单。
3. **坐席目录。** 认领或转交前，当前用户及目标用户需要本租户活跃的 `AgentProfile`；会话容量受目录中的 `max_concurrent` 限制。排班与主管代管需要后续独立业务规则。
4. **渠道送达。** 网页回复由平台时间线呈现；邮件／微信需要已配置的出站传输与健康状态。API 接受回复不等于第三方渠道已送达。
5. **搜索与规模。** 当前搜索为数据库精确过滤与 `ILIKE`，须在生产规模数据集上测量查询计划，再决定索引。不得仅为“架构完整”引入新搜索基础设施。
6. **AI 话术。** 当前副驾展示已有 AI 建议并允许人工编辑；“重新生成”需要独立的授权、成本配额、引用校验与失败策略，尚未实现，界面用“刷新建议”准确表述。
7. **附件语义。** 当前上传只关联工单证据；客户可见附件发送需独立的会话消息与渠道投递契约，未获支持前不展示为聊天发送功能。
8. **质量与回滚。** 新旧工作台按路由或租户标志灰度；生产发布需要真实渠道、跨租户、并发认领、重复投递、SLA 与性能验收结果。
